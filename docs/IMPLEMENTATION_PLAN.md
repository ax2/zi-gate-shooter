# 最小可玩版本实施计划

Stage-00 / 2026-10-11。**这是开发计划，不是已执行工程。** 目前没有package.json、src、依赖安装、测试脚本、构建命令或运行产物。只有用户明确说“开始开发”后执行以下阶段。

## 1. 模块职责与数据归属

不预先创建以下源码目录；命名只表示未来职责。优先纯规则与表现分离，不为小项目引入复杂ECS框架或服务后端。

| 模块 | 唯一负责的状态/输入输出 | 关键边界与验收 |
|---|---|---|
| Session/Clock | runId、游戏状态、固定步、暂停/恢复/重开 | 唯一模拟时钟；失焦自动暂停、需手动恢复；无补发 |
| Input/Viewport | 拖动/键盘→逻辑坐标与移动意图 | 不瞬移、不越界；适配不改规则 |
| Combat | 发射快照、弹丸、连续碰撞、生命与死亡事件 | 最近目标，单弹一次；伤害不由特效回调发起 |
| Reward/Progression | 箱/门/掉落状态、row锁、阶级/加成/超载 | 统一事务提交；(runId,id,generation)去重 |
| Director/Reachability | 模板、种子、轮次、危险时间表和合法路径 | 安全回退；不追着玩家DPS改HP |
| Enemy/Boss | 3普通+精英行为，首领状态机 | 攻击预告有可达安全路；胜利只推进一次 |
| Presentation | 场景、实体动画、特效、声音、镜头 | 消费只读事件；不改变碰撞、奖励和计时 |
| HUD/Flow/Storage | 开始、设置、暂停、结果、本地最高分 | 只保存带版本的设置/最高分；损坏存储回默认 |
| Config/Diagnostics | 数值、波次、效果预算、调试采样 | 单位明确、启动时校验；本地调试默认关，无上传 |

依赖方向：输入→模拟步→碰撞/事件排序→奖励与战斗状态提交→导演器调度→表现与HUD。配置为只读输入。表现层不反向修改规则；每次重开由Session销毁或清空所有本局资源，再创建新runId。

统一事件至少携带 runId、实体代次、模拟时间、类型、有效伤害或奖励、目标ID。掉落与门结算保留本局最小去重集合，已不可能再到达的事件及时清理；不能为了去重无限保留所有历史子弹ID。

## 2. 时间、预算与稳健性设计

拟定固定步1/60s；同一模拟时长在不同渲染帧率下得出相同规则结果。渲染延迟使用累积器，最多单帧5步；长卡顿超过可恢复预算时显式自动暂停并提示继续，不跳过危险、不一口气补发大量攻击。失焦直接暂停；用户恢复时丢弃墙钟间隔。慢设备墙钟耗时与模拟时间须分别记录，不能用慢模拟假装60帧。

候选活跃对象上限：我方弹80、敌方弹48、普通敌人24、精英1、首领1、箱/门实体合计6、掉落2。T3最多24弹/秒×1.2秒≈29个在途弹，80留余量；超载只变伤害不增加碰撞弹。临界情况下先限制后续生成并清理出界对象；活跃奖励不能因为池满被复用。任何逻辑池溢出记为验证失败，不能悄悄丢子弹改变DPS。表现池可按美术规格降级。

最高分/设置本地存储失败时转内存状态，不阻止游玩；不保存未结束局进度。无登录、后台、云存档或遥测。文件资源缺失需明确错误或标记降级，不能以占位资源冒充正式版本。

## 3. 按依赖推进的阶段

| 阶段 | 工作 | 退出条件 | 当前状态 |
|---|---|---|---|
| Stage-00 设计 | v0.2、美术规格、模块计划、验证矩阵、长期档案 | 规则可实现、未知有标注、档案可追踪 | 文档完成，未获方向批准 |
| Stage-01A 方向与基础 | 收到开发授权；核查平台/设备/版本；制作3关键状态候选图；建立最小工程与模拟时钟 | 依赖版本可复现；视觉方向可审阅；基础输入正确 | 未执行 |
| Stage-01B 内部机制切片 | 射击→箱破→拾取→T2；门升档→过线；死亡/暂停/重开 | 奖励、命中、同刻和上限用例通过；可玩但明确为内部占位 | 未执行 |
| Stage-01C 90秒正式可视切片 | 三阶段武器、完整敌种/精英/首领、配套素材、声音、HUD | 真正可操作90秒核心体验；5关键状态可读；至少一轮连接成功 | 未执行 |
| Stage-02 无尽 | 8模板、可达性、轮次封顶、成长补机会/超载、种子 | 多种子公平初筛、3轮完整连接、20分钟验证及风险记录 | 未执行 |
| Stage-03 验收与打磨 | 真机/桌面、设置与存储、性能、人工体验、档案发布 | 指定设备达标；缺项明确，用户可评审 | 未执行 |

Stage-01A/01B可先完成纯规则验证，但未经美术方向审阅不批量制作正式资产；Stage-01C不能用占位图形退出。最小可玩完整交付以Stage-01C加至少一次无尽连接为门槛；长局无尽质量到Stage-02/03评估。

首次开发先做单个箱子+单个门的完整链，之后才加更多敌人。首领依赖战斗、暂停和奖励事务稳定；无尽依赖至少一个可验证的首循环，不能用随机刷怪替代。既有工程如后来出现，先检查再接入，不重建覆盖。

## 4. 每阶段记录和验收材料

阶段开始时创建目标/工作日志，过程中记录发现、变更、偏差、检查、遗留和决策；结束时保存配置版本、种子、实际运行命令、构建标识、截图和测试结果。

移动端/桌面截图归档到技术博客screenshots对应Stage；记录视口、主题、特效档与结论。性能记录设备、浏览器版本、构建模式、分辨率、DPR、帧时间P50/P95/P99、峰值对象和内存趋势，人工观察单列，不混为自动测试。

H5原型交付不代表原生应用或微信小游戏完成。若以后确认Windows版本，保留完整运行目录和EXE，不打ZIP；本轮没有可运行构建。
