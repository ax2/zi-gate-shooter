## 1. 上一段对话的结论

用户描述了一类小游戏：竖屏、角色位于底部、场景与目标从上向下推进，持续出现敌人，击杀增加分数，射击装备提升属性，采用无尽模式。游戏元素应少，但画面要爆裂、刺激、清晰、精细，有强烈视觉冲击。

最初曾按“纵版卷轴射击”讨论。随后用户明确补充：**对着装备、箱子或数字门持续开枪来升级。** 因而规划方向修正为：**数字门射击 / 武器进化跑酷 / 跑酷射击**。这些名称用于描述与检索，不是要求套用某个统一的官方分类。

此前提及 Weapon Craft Run、War Survival: Last Shooter、Weapon Master 等作为玩法线索，以及 Sky Force Reloaded、Phoenix 2、CYGNI 等作为视觉线索。用户没有指定任何一款为精确复刻对象，也没有提供原游戏截图、视频、素材或代码。不要把这些游戏的具体机制、是否无尽或美术表现当成本项目已经确认的事实。后续确需逐款对照时，再核查官方资料。

**本项目复刻玩法体验，自行设计角色、美术、音效、界面、名称和波次，不直接搬用参考游戏资产。**

## 3. 产品定位与核心体验

**一句话：**一款竖屏无尽数字门射击游戏，玩家左右移动、自动开火，把前方的箱子打碎、把数字门的奖励打高，再移动领取强化，用升级后的火力消灭不断出现的敌群。

核心循环：

**判断目标 → 射击投入 → 奖励变好 → 走位领取 → 火力形态升级 → 大规模清场 → 面临更强挑战 → 战败结算并重开。**

最重要的决策不是“要不要按攻击键”，而是“有限时间里的子弹应该打在哪里”。例如：左边装备箱快碎了，右边数字门再打几枪就能升一档，但前面的冲锋怪即将靠近。

三条设计原则：升级的结果要看得见；每次重要击杀要有重量；特效再强也不能遮住危险、奖励数值与路线。

不把项目做成抽卡、合成经营、基地建设、多人联机或复杂技能树。不要把大量系统当成丰富细节的替代品。

## 4. 视角、操作与基本规则

### 4.1 场景与输入

采用斜俯视的单条战斗跑道。主角位于逻辑画面约 80% 高度，背景、敌人、箱子和数字门向下推进。跑道可用三个视觉分区辅助选路，但玩家横向连续移动，不强制三车道跳格。

移动端采用相对拖动，避免按下时角色瞬移到手指位置；底部留手指操作区。桌面支持鼠标拖动及 A/D、左右方向键。主角横向速度限制在配置内，手指拖得再快也不能绕过可达性约束。

默认自动向上射击，不自动跨路线锁定目标。主炮与副炮遵循清楚的前向弹道，玩家必须移动才能改变主要攻击目标。

保持固定逻辑坐标。高瘦屏和桌面宽屏用适配与留边处理，不拉伸角色或改变碰撞结果；关键界面避开系统安全区。美术透视不能导致“看得见却打不到”。

### 4.2 生存、得分与重开

初始生命建议 3 格，碰撞敌人或敌弹扣 1 格，受伤后约 1 秒保护，避免同帧多次扣血。敌人离开屏幕只损失潜在分数，不凭空扣血；第一版不加入第二套基地生命。

击杀得分，打箱子或打数字门本身不刷分。连击按击杀维持，受伤清空；无敌人可打的奖励专段冻结连击衰减，不让选奖励天然破坏连击。

生命归零进入结算：本局分数、存活时间、最高武器阶段、本地最高分、立即重开。重开清空本局战力、目标、子弹、计时器、订阅与粒子，保留设置和最高分。

暂停冻结全部模拟时间，包括刷怪、子弹、无敌、超载和连击。恢复时不补发暂停期间的攻击或波次。失焦后自动暂停，需明确恢复。

## 5. 两类核心成长目标

### 5.1 装备箱：越打，耐久越低

外观为可破坏机械箱。显示装备预览、目标阶级、剩余耐久与耐久条。命中减少耐久，出现裂纹、局部闪光与碎片。

状态为：`完整 → 受损 → 破碎 → 掉落物 → 已领取 / 已错过`。

只有打碎才出现装备；只有接触掉落物或进入小范围拾取半径才获得奖励。不要“打一下就升级”，也不要在破碎和拾取时重复发奖。未击碎的箱子作为实体障碍，接触会伤害玩家，第一局用外观与提示说明这一点。

掉落物继续随跑道下移，保留短暂可拾取时间；飞出屏幕后回收。小范围吸附只能帮助最后一段收取，不能隔着跑道吸走没选择的另一件奖励。

箱子预览固定奖励：T2 箱不会让已是 T2 的玩家直接升 T3。拾取高阶装备时取当前阶级与奖励阶级的较高值；重复或低阶装备转为明确显示的超载充能。转换数值可调，建议 30 点。

### 5.2 成长数字门：越打，奖励越高

外观为有可射击能量面的门，显示属性名称、当前奖励与升档进度。第一版只用正向加法奖励，不加入负数门、乘法门或复杂算式。

状态为：`可射击 → 累积进度 → 奖励升档 → 穿过结算 / 错过`。

射击增加能量 E，根据阈值提升显示奖励，例如“火力 +10% → +15% → +20% → +25% → +30%”。显示值是**穿过门后获得的奖励**，不是剩余生命，也不是每命中一次就即时加到角色身上的属性。

奖励只在玩家穿过该门时结算一次。跨门前把奖励打得再高也不即时生效。数字门本身无碰撞伤害；门体可阻挡我方子弹，第一版命中后消耗该弹，避免穿透后方目标带来不清楚的收益。

一排多个门是互斥选择：跨越领取线时，在覆盖玩家位置的门中选择中心距离最近的一扇（距离相同按稳定编号选择），使用 `rowId` 锁定该排，其他门失效。不能横扫一排同时领全部奖励。箱子与门并排的普通奖励段不自动套用门组互斥规则，是否能兼得由射击时间和走位决定。

### 5.3 命中与结算约束

奖励能量按有效伤害累积，不按画面里的光点数量累积。多炮管每弹伤害必须计入总输出；不允许每增加一根炮管便意外重复叠加整套伤害。

同一个穿透弹或激光在未来加入时，需要定义每目标命中频率；不能每渲染帧重复充能。第一版不实现穿透和持续激光，先保持命中模型简单。

每个奖励实体与门组都需要稳定标识和一次性结算保护。对象回收复用时清空历史领取、伤害与事件状态。

## 6. 武器成长与数值模型

### 6.1 第一版只做三阶段，不做三套复杂武器系统

| 阶段 | 可见形态 | 候选发射规则 | 基础理论输出 |
|---|---|---|---|
| T1 | 单管机枪 | 每秒 8 轮，每轮 1 弹，每弹 4 伤害 | 32 伤害/秒 |
| T2 | 双管机枪 | 每秒 6 轮，每轮 2 弹，每弹 4 伤害 | 48 伤害/秒 |
| T3 | 双管 + 双副炮 | 每秒 6 轮；两枚主弹各 4 伤害，两枚副弹各 2 伤害 | 72 伤害/秒 |

这些是全部弹丸命中同一目标时的理论值，实际输出需考虑距离、遮挡与走位。炮管展开以近轴平行弹道为主，不要过早扩大到同时自动攻击所有路线。

每次阶段升级同步改变炮管外观、枪口效果、弹道密度和声音。升级的主收益来自形态变化，不只是一行浮动数字。

### 6.2 门的加成与无尽数值收敛

建议火力门按百分点累加，而不是连乘。例如两次 +20% 得到基础伤害 ×1.40，不是 ×1.44。

候选公式：

`实际伤害 = 阶段弹丸基础伤害 × (1 + 本局火力加成) × 超载倍率`

本局火力加成建议上限 +100%。满级后不再生成无效火力门，改生成显示“超载充能 +数值”的数字门，沿用同一套射击升档与穿过领取逻辑。接近上限时，清楚显示实际可领取增幅；不要承诺 +30% 实际只加 +5% 却没有提示。

超载能量 100 点触发约 6 秒强化，倍率建议 1.35；激活时扣除 100 点。期间可以继续充能，但不叠乘倍率、不刷新当前持续时间，结束后才判断下一次触发。能量上限 100。

超载提供更强弹道、音效和机体光效，但不能大量增加有碰撞的弹丸来替代伤害倍率。满成长后仍有清场峰值，不必继续把所有数值无上限乘大。

### 6.3 数字门候选阈值

| 累计有效伤害 E | 火力奖励 | 满成长后对应超载奖励 |
|---|---|---|
| 0 | +10% | +10 点 |
| 24 | +15% | +15 点 |
| 56 | +20% | +20 点 |
| 96 | +25% | +25 点 |
| 144 | +30% | +30 点 |

门的奖励和阈值进入配置。若一次命中跨过多档，必须正确显示最终档位并只播放受控的升档反馈。到上限继续命中不再增长，用明确的满档状态提示玩家换目标。

第一只升级箱建议耐久 48，第二只建议 144。目标是第一只容易打碎、第二只需要有效投入，而不是要求玩家在极短窗口内精准计算。需在真实弹道、卷轴速度和拾取距离下验证。

## 7. 敌人配置与战斗职责

第一版建议三类普通敌人、一类精英和一个首领，复用同一套机械美术语言。

| 单位 | 主要职责 | 初始生命候选值 | 击杀基础分 |
|---|---|---:|---:|
| 小型无人机 | 成片出现，提供扫射与连锁爆炸的爽感 | 12 | 10 |
| 冲锋单位 | 预警后沿固定路线加速，要求及时走位或清除 | 24 | 20 |
| 装甲单位 | 较慢、耐打，制造“继续打箱子还是先清怪”的取舍 | 80 | 50 |
| 精英 | 组合普通威胁，提供较大击杀反馈 | 240 | 150 |
| 首领 | 分阶段攻击与明显弱点，检验成长结果 | 1200 | 1000 |

以上生命只用于首轮校准，不是通用难度结论。首领不做一整屏没有预警的随机弹雨，使用路线预警、扫射与短暂安全窗口。首领战背景继续滚动，首领可相对镜头保持在上方。

首领击败后建议恢复 1 格生命，上限 3 格；清理残留攻击，给短暂恢复段，再接下一轮。下一轮不回到开局菜单，也不重置本局装备。

## 8. 首段体验与无尽导演器

### 8.1 先打磨约 90 秒的体验片段

这是一段目标节奏，不是 90 秒倒计时通关。首领没被击败就继续战斗，不能到点自动杀死首领或重置本局。

| 目标时间 | 内容 | 验证的问题 |
|---|---|---|
| 0–8 秒 | 少量小怪；轻量提示左右拖动、自动射击 | 不读说明能否开始玩？ |
| 8–18 秒 | 容易打碎的 T2 装备箱，旁边保留通行路线 | 是否理解打碎后还要领取？ |
| 18–32 秒 | 第一次数字门；给足时间看到奖励升档 | 是否分得清耐久与奖励？ |
| 32–48 秒 | 敌群和首个精英，兑现双管火力 | 升级后是否明显更爽？ |
| 48–62 秒 | T3 装备箱与成长门构成取舍 | 有没有选择，而非只需站中间？ |
| 62–72 秒 | 大批脆弱敌人，展示高阶火力与超载反馈 | 特效强时是否还能看清路线？ |
| 72 秒后 | 首领；击败后恢复并连接下一轮 | 核心循环是否闭合？ |

演示模式可以固定随机种子并安排易获得的高阶成长；普通模式不能伪造拾取或暗中自动升级。没拿到 T3 的玩家仍继续，不强制补发，只调整后续机会。

### 8.2 无尽不是完全随机撒怪

采用手工编排的小波次模板与带种子的随机调度，模板包含战斗段、奖励段、压力段、释放段和首领段。先验证一批模板，再增加组合。

难度由轮次和公开的阶段规则控制，逐步改变编队、敌种、攻击组合与有限的生命倍率。不要因为玩家刚捡到加成，就立刻按其实际输出同比提高所有敌人生命；升级后的清场优势应该保留。已生成敌人的生命不能追着玩家伤害变化。

卷轴速度、怪物数量、生命倍率和特效数量分别设置上限。到达数量预算后用编队和攻击时序维持挑战，不无限堆对象。对更长局数使用阶段表或有界参数，不盲目指数增长造成数值溢出。

### 8.3 可达性与公平性

同一时段至少有一条可达的安全路线。危险预警必须覆盖反应和实际移动时间：

`可用时间 ≥ 横向距离 / 最大横移速度 + 反应余量 + 安全余量`

奖励不是全部保证获得，但必须有合理成功机会。不要把箱子放在生成后已来不及击碎的位置，不要用两个同时到达的必撞障碍封死跑道。自动检查只能作为初筛，还需要人工试玩验证。

## 9. 美术、特效与声音

### 9.1 统一方向，而不是堆素材

建议主题为“科幻机械跑道上的火力突围”：深色工业地面、冷色机体与我方能量、暖色爆炸、清楚的危险形状。颜色仅作当前方向建议，之后用完整战斗概念图确定。

场景通过循环地表、侧边建筑、移动阴影、远层烟雾和少量前景碎屑表现纵深。主角和敌人用炮管、装甲缝、引擎、受损变化增加细节；不要只给几何色块外面套辉光。

当前没有经用户批准的概念图。上一段展示的参考图片不是本项目素材，也不是已经批准的设计稿。后续先确定正常战斗、升级瞬间和高火力战斗三个关键状态，再建立配套素材清单。

正式可视版本需要一致的角色状态素材、敌人素材、箱体完整/破损/破碎状态、门体、掉落物、弹丸和多层背景。界面文字、实时数字、判定框与游戏逻辑由代码实现，不烘焙进一张不可交互的整屏图片。

### 9.2 反馈分级

| 事件 | 表现建议 |
|---|---|
| 持续射击 | 枪口脉冲、弹道核心和短拖尾、短促连续音效 |
| 箱子命中 | 局部火花、机械震动、裂纹累积；耐久清楚下降 |
| 门被命中 | 局部能量涟漪、进度变化；升档才放大数字反馈 |
| 箱子破碎 | 外壳碎裂、冲击波、装备露出；不要提前触发角色升级 |
| 拾取升阶 | 装备能量汇入、炮管变化、声音提升；控制总时长 |
| 普通击杀 | 小型爆炸和少量碎片；不强烈摇屏 |
| 精英击杀 | 更深的爆炸声、较大冲击波、局部镜头反馈 |
| 首领击杀 | 多点连续爆炸、残骸、短暂慢动作、集中结算反馈 |

爆炸、碎片和分数浮字应有上限及合并策略。大批敌人同时死亡时，保留清场的整体节奏，不为每个对象播放最强闪光与震动。

### 9.3 清晰度约束

把地面与装饰压到背景；主角轮廓、敌方攻击、门奖励、箱子耐久和走位空间属于最高可读性层。敌我弹丸不仅颜色不同，形状和动势也应不同。

默认不使用高强度全屏白闪。提供震动关闭/弱/标准、闪光弱化、画质、音乐和音效开关。弱化特效不能同时隐藏危险预警。

候选界面字级以手机实际显示尺寸校验，不只看设计分辨率。门的主奖励数字建议至少相当于 24 CSS 像素，属性标签至少相当于 14 CSS 像素；使用清楚的背景或描边，不用大面积辉光糊掉字。

## 10. 第一版范围

### 必做

一个主角，三阶段武器，两类成长目标，三类普通敌人，一类精英，一个首领，一个可循环场景。完整支持开始、战斗、暂停、设置、死亡、结算、重开，以及本地最高分。

先完成约 90 秒关键体验，再实现持续连接的无尽结构。性能和视觉验证必须包含高火力状态，不能只在空场景检查。

### 后置

武器充能台、负数门或乘法门、激光与追踪弹等不同武器分支、多个角色、更多场景、局外解锁、挑战任务。

### 暂不做

账号、登录、排行榜后端、支付、广告、联网对战、抽卡、基地经营、复杂背包、永久战力养成。不要未经用户要求建立这些外围系统。

## 11. 界面布局建议

主界面简短展示游戏名、开始按钮、最高分与设置入口，不制作复杂营销页或多层大厅。

战斗顶部显示分数、生命与暂停；武器阶级和超载进度放在不挡跑道的位置。不要让属性表占据大半屏幕。首领生命条只在首领战出现，避免压住顶部核心信息。

结算突出本局成绩与立即重开。首局教学只用短提示，出现一次后退出，不连续弹窗打断射击。

## 12. 工程建议与实现边界

### 12.1 默认技术方向

没有现有仓库或平台限制时，建议先用 **TypeScript + Vite + Phaser** 开发浏览器原型。Phaser 官方提供 Vite/TypeScript 相关模板和脚手架选择，支持这一选型路径，见 S1。这里不固定主版本，不把历史文章中的版本号当作当前最新版。

这个项目暂不需要 React、Next.js、数据库或后端。已有仓库存在时优先遵守现有工程，不为了符合本文而无必要重建。若最终目标明确为微信小游戏或原生应用，要单独确认目标运行环境、素材规格和适配成本；浏览器可玩不等于已完成这些平台的交付。

### 12.2 建议模块

```text
src/
  main.ts
  game/
    scenes/       # 启动、主界面、战斗、结算
    entities/     # 玩家、敌人、箱子、门、弹丸、掉落物
    systems/      # 发射、命中、奖励、成长、波次、特效、声音
    config/       # 武器、敌人、奖励、节奏与画质参数
    state/        # 本局状态、一次性结算与状态切换
    ui/           # HUD、暂停、设置
  assets/
  tests/
docs/
  GAME_DESIGN_HANDOFF.md
  DESIGN_DECISIONS.md
  IMPLEMENTATION_PLAN.md
  TEST_REPORT.md
```

这是职责示意，不是强制文件树。避免把刷怪、奖励、输入、绘制、音效与结算全部堆到一个巨型文件中。

### 12.3 必须落实的工程规则

射击、移动和持续效果基于模拟时间，不基于渲染帧计数。低帧率不应降低武器理论射速，也不应让门升档变快。采用可控时间步长，处理暂停、失焦和恢复后的大时间差。

高速弹丸需要避免越过目标漏判。碰撞遵循前方最近有效目标，明确子弹是否消耗。游戏判定与视觉粒子分离。

弹丸、敌人、碎片和浮字使用受控生命周期与复用策略。粒子、残骸、声音并发数量设置预算；高火力状态下也要正常回收。门和箱子的状态变化走一次性事件，不允许重复监听累积。

数据集中配置，至少包含射速、每弹伤害、门阈值、生命、移动速度、箱子耐久、波次表、掉落半径、粒子预算和屏幕震动强度。调手感不应修改多个逻辑文件。

只在本地保存最高分和设置，并提供存档版本与失败降级；不收集个人信息、不默认上传遥测。调试事件可在本地记录，默认关闭。

### 12.4 性能目标，不是性能承诺

目标设备上以稳定 60 帧为优化方向，并提供弱化特效档。具体目标设备尚未确定，不得声称“所有手机稳定 60 帧”。

报告真实设备或模拟环境、视口、画质档、构建模式与测试场景，至少记录高火力和首领状态的帧时间，以及长局对象是否持续增加。必要时先减少装饰碎片、烟雾和后处理，不能减少敌方危险信息。

## 13. 建议里程碑

| 阶段 | 交付物 | 退出条件 |
|---|---|---|
| M0：完善设计 | 修订规则、默认决策、初始配置、关键状态视觉方向、最小开发任务 | 数字门、箱子、领取、伤害与循环没有关键歧义 |
| M1：可玩闭环 | 移动、射击、两类目标、武器三阶段、敌人、死亡与重开 | 不靠作弊即可完成“打装备—领取—变强—清场” |
| M2：视觉成型 | 配套正式素材、分级特效、声音、关键状态画面、设置 | 非几何占位版本，强效果下信息仍可读 |
| M3：无尽与稳健性 | 模板波次、首领循环、数值上限、性能优化与测试报告 | 多轮连续游玩、反复重开不累积错误或对象 |

M1 内部机制验证允许短期占位，但必须明确标记，不能作为用户要求的最终视觉交付。实施前先把视觉方向定清楚，不能最后才想“高清爆裂”怎样落地。

## 14. 验收与测试清单

| 编号 | 场景 | 通过条件 |
|---|---|---|
| T01 | 触控、键盘与窗口变化 | 横向连续移动且不越界；按下不瞬移；比例与碰撞保持一致 |
| T02 | 自动射击 | 持续开火；30/60/120 帧测试下按模拟时间统计的射速一致 |
| T03 | 装备箱 | 耐久下降；破碎后才掉落；拾取前角色不升级 |
| T04 | 数字门 | 命中提高进度和显示奖励；穿过前角色不加成 |
| T05 | 单次结算 | 多弹同时命中、停留在触发区、对象复用，都不重复发奖 |
| T06 | 互斥门组 | 同排最多领取一个门；另一门明确失效 |
| T07 | 加法与上限 | 两次 +20% 得到 +40%；接近上限提示实际奖励；满成长后生成有效替代奖励 |
| T08 | 超载 | 满 100 触发；倍率不叠乘；不无限刷新；暂停后剩余时间不变 |
| T09 | 武器形态 | T1/T2/T3 外观、弹道、声音可分辨；多管输出符合配置 |
| T10 | 升级边界 | 低阶或重复装备不降级、不跳级；转换奖励准确且有提示 |
| T11 | 伤害与结算 | 同帧多次接触遵守保护期；死亡只结算一次 |
| T12 | 暂停与失焦 | 刷怪、无敌、连击、超载一起冻结；恢复不瞬间补发积压事件 |
| T13 | 无尽循环 | 首领死亡后进入下一轮；不强制在 90 秒结束；本局成长保留 |
| T14 | 重开压力 | 至少连续重开 20 次，确认敌人、计时器、订阅、声音与粒子没有持续累积 |
| T15 | 长局压力 | 固定种子持续运行至少 20 分钟；检查对象数量、数值范围与帧时间趋势 |
| T16 | 公平生成 | 多种子检查危险组合和可达性；人工试玩无不可避免的封路 |
| T17 | 视觉关键状态 | 普通战斗、箱子破碎、门升档、T3 群怪、首领爆炸均可读 |
| T18 | 画质与静音 | 弱特效不隐藏预警；设置保存；音效开关有效；首次开始正确初始化声音 |
| T19 | 资源与控制台 | 正式素材加载正常；无未处理错误；丢失素材有明确降级和记录 |
| T20 | 构建与记录 | 实际执行可用的类型检查、测试和构建；记录通过、失败与未执行项 |

手机显示建议至少检查 360×800、390×844、430×932 和桌面宽屏。它们是测试视口，不等同于真实设备性能验证。

视觉验收需要实际运行截图或录屏，不得只用代码截图、概念图或“构建成功”代替。尚未生成正式素材、没有设备或没有执行测试时，应如实标记未完成。

## 15. 主要风险与处理

| 风险 | 处理方向 |
|---|---|
| 做回传统纵版射击 | 把装备箱与数字门作为主要成长方式；先验证射击投入与领取的选择 |
| 看起来只是移动色块 | 先定完整关键状态与独立素材，再做正式可视版本 |
| 爆炸遮住数字或危险 | 分层、粒子预算、局部特效、弱闪光与震动选项 |
| 无尽模式数值失控 | 加法加成、阶段上限、超载转换、有限刷怪预算 |
| 升级后感觉没有变强 | 不即时同比抬高敌人生命；同步改变炮管、弹道和声音 |
| 一直站中间就够了 | 前向射击，不跨路线自动锁定；用奖励与威胁的空间分布产生选择 |
| 选装备等于白挨打 | 检查目标到达时间、击碎时间、横移时间与安全路线 |
| 手机掉帧改变玩法 | 模拟时间与渲染解耦；高速弹丸检查；缩减非关键视觉负载 |
| 范围膨胀拖慢落地 | 坚持少量对象，把投入集中到核心闭环和画面反馈 |
