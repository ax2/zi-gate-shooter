# 新 Codex 会话启动指令

把下面内容粘贴到新的 Codex 会话。另提供本包中的 `docs/GAME_DESIGN_HANDOFF.md`；有项目目录时，把文件放到 Codex 能读取的位置。不要假设新会话已经知道旧聊天。

请接手我的游戏项目，先以游戏策划和技术负责人的视角完善方案。本轮先完善策划，不自动开始写游戏或搭建工程。

请先读取 `docs/GAME_DESIGN_HANDOFF.md`、`AGENTS.md` 和项目已有说明。若文件作为附件提供，读取对应附件，不要只凭文件名猜测内容。

已确认需求：我要做一款竖屏无尽数字门射击游戏，角色位于底部，场景、敌人、装备箱和数字门从上向下推进，击杀敌人得分。核心不是单纯打怪掉装备，而是对着装备、箱子或数字门持续开枪，把箱子打碎、把门的奖励打高，再取得强化。游戏元素要少，但画面必须爆裂、刺激、清晰、精细，升级后要明显感到火力变强。

当前默认方案：左右连续移动、自动射击；一名角色、装备箱和成长数字门两类目标、三阶段武器、三类普通敌人、一类精英、一个首领和一个循环场景。先打磨约 90 秒的关键体验，再扩展为无尽。箱子打碎后仍需拾取，数字门只在穿过时结算，同排互斥门只领取一个。充能台、复杂武器分支和局外经营后置。

默认技术建议是 TypeScript + Vite + Phaser 的手机浏览器原型，默认美术建议是精细科幻机械风。平台、技术、角色外观、风格和具体数值还没有被我正式确认；有现有工程就先检查并尊重现状。当前没有已完成代码、正式素材、批准的概念图或实测性能，不要声称已有这些成果。

请先完成：
1. 简要复述你对项目的理解，区分已确认需求、建议和未知项，不重复问已经确定的问题。
2. 检查奖励结算、成长上限、命中逻辑、首领循环、可达性和无尽节奏的漏洞，并给出可落地修订。
3. 在不增加大量系统的前提下，补齐核心交互、初始配置、美术与特效规格，解释关键取舍。
4. 输出最小可玩版本的模块拆分、开发顺序和验收条件；存在工作区且允许写文档时，保存设计决策与实施计划，但暂不写游戏代码。

不要把“高清爆裂”理解成几个发光色块，也不要为了视觉效果挡住数字和危险。不要复制商业游戏素材，不要擅自添加登录、支付、广告、后台、多人或基地经营。

当我明确说“开始开发”后，再核实依赖与工程、确定视觉素材方案、实现可玩闭环，并用实际运行结果验证。所有候选数值都需要后续试玩调整，所有尚未执行的测试都要如实注明。
