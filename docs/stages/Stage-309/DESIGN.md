# Stage309 设计：分数回收舱与有界投送

首个300分分支包仍为3份本系材料，原pending/分支选择保持。后续每次2份材料依次轮换、每第三次1维修保持；前11个阈值仍75n²+225n（至11550分），之后下一间隔封顶1800分。它限制长期等待，不自动购买科技或跟随DPS抬高敌人耐久。所有数值是待试玩候选。

ScoreSupplyLedger只记四种已有内容，最多4条待投送，满池合并承诺金额与分数来源，空位恢复后才生成物体。满池只复用仍存活的同内容分数舱，不把新分数承诺静默塞进普通旧物；原普通掉落仍可以合入现有同内容分数舱，实际总内容与分数来源金额分别记账。投送刷新真实寿命，舱最多留30秒（先出界则结束）；拾取前不入仓，错过记失效，不远程补发。每个内容满足earned=issued+pending、issued=collected+expired+active。死亡不投送、冻结世界，开新局重置本局承诺。

机械浮舱复用已有原创crate-v1九格图中的开放舱体与少量碎片，内容图标/实际数量大于装饰，开放状态说明无需射击，自动子弹穿过，飞近回收。危险仍最后绘制。弱档保留舱体/内容/数字、去浮动尾光和碎片；实际拾取才有回收效果。原图和派生PNG字节不改。多舱连收时专用回执合并各内容图片及实际主炮变化/维修结果，避免维修覆盖材料；点击材料回执进入现有图片付费装配，不免费装组件。暂停/菜单不消耗模拟寿命。

验证将分开：旧版满池缺奖复现、孤立有界队列/过期/合并守恒，实际Runtime正常获取/回收/点击/付费和长局节奏，原始图SHA/真实离屏图审计。Native不替代浏览器控制台/实际事件桥接、真人平衡趣味或设备FPS；仍保留已知浏览器策略边界，不反复要求用户切前台。

新舱以击杀点为基准尝试邻近位置，优先避开已有掉落的125×135逻辑半间距，中心限制x70–650/y260–1125以保护HUD与底部控件；拥挤无全空位时选重叠最少点。只在生成新舱时选位，已存在舱合并不瞬移。仍是任意击杀位置附近投送，不恢复固定排程门箱。

回执维修显示实际回生命或“满”；成功单件与整套付费装配后结束旧补给回执，避免把购买带来的武器变化混算为之后的拾取收益。拒付在提前返回处不会清掉回执。

分数舱选位还暂避当前已击破机体的位置，给稍后才结算的行动战利留位置；只是生成时避让，吸附后邻近物仍可能贴近。
