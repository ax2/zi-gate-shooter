# Stage-26 / 双平台候选包清理

目标：候选构建只包含当前源码资源，防止旧素材或误放文件继续进入发布目录。运行玩法和美术保持 Stage-24 基线。

发现：微信和 Android 网页脚本只递归覆盖复制 assets，不清理历史输出；微信 manifest 会把残留也作为当前文件记录。因此包体清单正确并不能证明没有旧资源。

修改：构建前清理固定白名单 build/wechat 或 build/android-web；解析真实项目路径，拒绝重定向 build/output 目录以及任意输出名称。微信清理前读取已有 AppID，环境变量仍优先。不能把个人配置或其他目录放在这些生成目录中。

验证：新增隔离临时项目回归，实际执行两次两个平台脚本，删除源素材、加入外来文件后再构建；检查残留消失、有效素材/许可保留、微信 AppID 保留与 manifest 精确目录。额外验证 junction 重定向拒绝且目标文件保留。3项通过，892ms。旧脚本隔离负对照复现两端残留；完整24文件141项99.48秒通过，类型/网页通过，Android42秒/7585619字节、微信3061599字节，APK哈希与Stage-24一致。详见TEST_REPORT。

Android 环境：Stage-25 的 QEMU 残留继续 offline，不能用本轮构建代替原生运行；两项 instrumentation 未执行。微信开发工具、双方真机、人评和发布审核仍待验。无新增游戏画面，不制作游戏截图。
