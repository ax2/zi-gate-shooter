# Stage-08 / 微信音频异常隔离

日期2026-10-11，起点5607624。目标为音频API失败时仍可战斗/暂停，并控制坏节点及重试频率；不把静音容错当作音效验收。

当前微信sound调用createInnerAudioContext/配置/play及silence.stop没有异常边界。同步播放异常会进入共享模拟的运行异常分支；stop异常可能从onHide传播。先用实际微信bundle注入平台故障取得负对照，再修复适配器、验证节点清理与恢复。不改玩法/美术/Android生产入口。

原始来源和规则已按AGENTS/README/策划与Stage-07读取；既有Android模拟器已停止，无待轮询任务。微信工具/真机/人工音效听审仍待验。

## 实施与验证

- 扩展既有实际bundle VM夹具，可注入平台音频创建/配置/play/stop失败，仅观察绘图文字/位置与平台节点计数，不注入World。
- 旧bundle负对照9项中4失败/5通过：前三种故障渲染“运行异常，请重新开始/重新加载”，stop故障从hide抛出。原始stage08-before.txt保存最终有效负对照；最初夹具在提前位置断言处失败，移除该音频测试不适用断言后重新取得直接错误页证据，未将旧输出当成最终结论。
- 增加音频失败退避时间，当前候选5000ms；节点先加入池后配置以保证配置失败能清理。失败时先分离池/清busy，再逐节点stop/destroy并独立捕获异常；onError检查当前池身份，防迟到回调误清新池。普通silence仍复用健康节点，遇到stop失败才退休。玩法、数值、美术和Android入口未变。
- 类型检查与微信构建通过，候选537403字节。最终相关回归2文件16项通过，362ms：创建/配置/play故障不进错误页、半秒内不反复重试、5秒后健康工厂重新播放、hide停止异常安全、async error清理、旧回调不清新池、stop/destroy清理也抛出时仍可战斗/暂停，原多指与共享输入回归仍通过。
- 未重跑完整规则测试。没有微信工具/真机测试、听审或真实资源释放数据；VM节点destroy计数不是设备内存证据。无视觉变化及新增截图；Android继续Stage-06 APK。
