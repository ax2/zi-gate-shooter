## 取证失败与修订

第一次正常开局后立即切换视口，既有resize输入清理使目标回到x360，40.767秒仍T1。55.65秒才重新向x240拖动，错过两箱；70.8秒T1/火力60%/分20死亡，未遇首领。其后18.001秒361帧仅结果页，保留为失败，不能称首领证据。通过实际重开按钮重新开局，正常取得T2/T3。

第二次开局128.433～146.65秒362帧为正常第二轮推进，错过首轮首领。再尝试173.967～194.167秒时，复用函数捕获了旧词法作用域中的夹具句柄，402帧实际是静态夹具；原始目录normal-second-boss-frames已在校验路径后改名wrong-target-fixture-frames。对应正常诊断和独立截图仍来自run24，但这些JPEG绝不作为正常首领证据。改为显式cap参数后，从第三轮入场重新录制并逐帧视觉确认，未重开来掩盖问题。

所有原帧保留在代码本地build/qa/Stage-24。档案/outputs完整保留有效攻击/残骸/第三轮首领原帧；重复结果页、错误目标与错过首领的推进片段保留metadata和代表帧，避免把冗余截图当成有效证据。原始文件未删除。最终两页控制台警告错误为空，临时页关闭、视口复原；未改正常设置，首次死亡按游戏既有逻辑写入最高分（仍440）。
